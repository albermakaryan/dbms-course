-- 02 · schema types · denormalizing on purpose

Copy data only when all four hold

1

there is one source of truth, and it’s normalized

2

the copy is built from it by a query

3

the copy is rebuilt, never edited by hand

4

someone owns the rebuild and knows when it ran

passes · star schema: built from the OLTP tables every night

fails · customers.moneySpent: a copy of sum(orderTotal) inside the source of truth, right only if every insert remembers to update it

This course’s rule of thumb (not a published standard), based on Wikipedia, “Extract, transform, load”

The rule Lecture 2 promised. moneySpent fails because it lives inside the OLTP tables and depends on every piece of code that inserts an order also updating it. Part 5 checks whether it is still right today; the lesson is that it can drift and nothing would warn us.
