-- 03 · join · execution order

The joins run first

1

FROM + JOINs

2

WHERE

3

GROUP BY

4

HAVING

5

SELECT

6

ORDER BY

7

LIMIT

Every ON is applied at step 1, while the combined rows are built.

WHERE never sees the separate tables. It sees the joined rows.

After that, everything from Lecture 3 works on the joined rows exactly as on a stored table.

Source: PostgreSQL 16 docs, SELECT → Description (the order a query is processed in)

Lecture 3's order with one change: step 1 builds the combined rows. Demo: completed revenue per city (orders JOIN customers, WHERE status, GROUP BY city): Yerevan 82057.54, Gyumri 43495.52, Abovyan 11566.79, Vanadzor 8815.27. Keep this pipeline in mind: the WHERE-vs-ON trap in Part 4 comes straight from it.
