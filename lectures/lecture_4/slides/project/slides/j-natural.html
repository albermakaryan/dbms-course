NATURAL JOIN: the invisible condition

orders NATURAL JOIN sales joins on all 12 shared names:

orderID

orderDate

orderTime

channel

status

paymentMethod

quantity

unitPrice

discountPct

orderTotal

deliveryDate

rating

deliveryDate is NULL for every in-store order, rating for most. NULL = NULL is not true, so those rows are thrown away.

97

rows. Both tables hold the same 600 sales.

No error. And nothing in the query says which columns it used.

Sources: PostgreSQL 16 docs, “Joined Tables” (NATURAL) and “Comparison Functions” (NULL = NULL is null); 97 from Part 3

Demo: SELECT count(*) FROM orders NATURAL JOIN sales; Guess before revealing why. Only online orders that also got a rating have no NULLs in those twelve columns: 97. Add a column to either table next year and the answer silently changes. Always write ON or USING.
