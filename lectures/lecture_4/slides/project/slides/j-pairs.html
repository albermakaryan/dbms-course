A join is a filtered cross product. The database finds the matches faster, but the answer is always exactly this.

Sources: PostgreSQL 16 docs, “Joined Tables” (cross join = N × M rows) and “Planner/Optimizer” (every plan, same result); Part 3 queries

Demo live: (1) SELECT count(*) FROM orders CROSS JOIN customers; → 18000. Guess first. (2) The 9-row version: WHERE o.orderID IN (1001,1002,1003) AND c.customerID IN (2,6,26). Ask which of the nine lines are true. (3) Add AND o.customerID = c.customerID → 3 rows. (4) Rewrite as JOIN customers c ON c.customerID = o.customerID. JOIN alone means INNER JOIN. PostgreSQL never builds 18,000 rows: its planner picks a nested loop, merge or hash join by estimated cost, and every plan returns the same result (docs: Planner/Optimizer).
